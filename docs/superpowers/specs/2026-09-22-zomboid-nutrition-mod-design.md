## 1. 项目概述

在《僵尸毁灭工程》（Project Zomboid）中制作一个**营养仿真 MOD**，把原版"碳水/蛋白质/脂肪/卡路里"四维、只影响体重的营养模型，升级为**多维度营养素仿真系统**，让"吃什么、吃多少、怎么运动"真正决定角色的短期状态与长期成长。

### 1.1 核心目标

1. **食物营养细化**：11 项独立记账营养素（蛋白/碳水/脂肪/钠/钾/钙/铁/VA/VC/VD/B1）+ 派生热量。
2. **活动驱动消耗**：所有营养素都有消耗出口，按活动类型、强度配比、环境、属性联动动态结算——**摄入与消耗形成动态平衡**。
3. **储备积分与档位反馈**：营养状态 4 档（缺乏/不足/充足/盈余），吃好给 buff、失衡出 debuff；快营养素管即时战术，慢营养素以疾病进度为主、辅以轻量即时档位效果（统一四档）。
4. **体力耐力成长**：双门槛成长公式 + 肌肉分解机制，营养与训练共同决定 Fitness/Strength。
5. **营养疾病**：8 种末日高发营养疾病，容量对齐节奏触发，康复期营养状态决定恢复速度。
6. **体重完全接管**：我们的热量净额直接驱动体重，含增减重构成与体脂率派生量。
7. **保质期联动**：新鲜/陈腐/变质三档营养保留，四条加工路线各有不可替代的定位。
8. **UI 展示**：营养面板 + 7 天趋势 + 疾病详情 + 康复目标，风格完全对齐原版（Vanilla-Native）。

### 1.2 设计原则

- **单机优先**：逻辑以服务端/共享模块为主，预留多人接口，第一版不保证联机。
- **数据驱动**：食物营养表、消耗倍率、储备容量、疾病参数、档位效果全部集中配置，调参不动代码。
- **模块化**：数据层/储备/疾病/运动/成长/UI 各自独立，职责单一、可独立测试。
- **不直改属性值**：属性类效果只动 XP 获取率与状态系数，不临时修改力量/体格数值（可逆、无存档风险、不与原版 trait 封顶冲突）。
- **对齐原版**：耐力条机制完全复用；体重接管但平滑迁移；不破坏原版平衡边界。
- **康复需超量**：DRI 是维持量而非治疗量；储备回升与疾病康复要求 >100% 摄入（康复目标 ×1.5 DRI，见 4.7.1）。

## 3. 营养维度模型

### 3.1 营养素大类定义（11 项独立记账 + 1 项派生）

MOD 追踪以下营养素，**每项独立记账**（摄入/消耗/储备各有数值）：

| 营养素 | 单位 | 主要作用 | 消耗模型 |
|---|---|---|---|
| 蛋白质 | g | 肌肉修复与维持、力量成长 | 活动配比 + XP 驱动 + 受伤加速 |
| 碳水化合物 | g | 快速能量、爆发活动 | 活动配比（主力） |
| 脂肪 | g | 储备能量、体重构成 | 活动配比（低强度主力） |
| 钠 | mg | 电解质、耐力恢复 | 固定速率 × 活动/温度（出汗） |
| 钾 | mg | 电解质、耐力恢复 | 同上 |
| 钙 | mg | 骨密度、愈合 | 固定日周转 |
| 铁 | mg | 造血（贫血） | 固定日周转 + 受伤加速 |
| 维生素 A | µg | 夜视 | 固定日周转 |
| 维生素 C | mg | 免疫、伤口愈合 | 固定日周转 + 受伤加速 |
| 维生素 D | µg | 钙吸收调节 | 固定日周转（摄入侧另有日照合成通道，见 3.3） |
| B 族（B1 代表） | mg | 神经功能、疲劳 | 固定日周转 |
| **热量（派生）** | kcal | 体重驱动、成长门槛 | `碳水×4 + 蛋白×4 + 脂肪×9`，摄入/消耗两侧同公式 |

> 钠/钾/钙/铁拆分记账是疾病系统的前提（贫血/电解质紊乱/骨质流失分别依赖铁/钠钾/钙钙），罐头流钠超标不能掩盖钾钙缺乏。

### 3.2 每日需求参考值（DRI，配置于 `Nutri_Config.lua`）

| 营养素 | 每日参考需求 | 备注 |
|---|---|---|
| 蛋白质 | 75g | 属性联动后满力角色实际需求 ~90g |
| 碳水 | 250g | 活动量大时需求上浮 30%+ |
| 脂肪 | 60g | 罐头生态下易超额 |
| 钠 | 2000mg | 罐头流轻松 250% |
| 钾 | 3000mg | 罐头流 ~57%，新鲜食物压力点 |
| 钙 | **800mg** | 数据表须覆盖带骨鱼罐头/乳制品 |
| 铁 | 15mg | 肉类为主 |
| 维生素 A | 900µg | 胡萝卜 100g 即可覆盖 |
| 维生素 C | 100mg | 罐头 = 0，坏血病压力点 |
| 维生素 D | 15µg | 食物几乎不可达，依赖日照 |
| B1 | 1.2mg | 豆类/猪肉可覆盖 |
| 热量（派生） | ~1840 kcal | 三宏量合计，落在原版"维持"带内 |

### 3.3 维生素 D 日照合成通道

食物维D 几乎不可达，若无其他来源骨质流失将必然发生。新增日照通道：

- **条件**：白天 + 室外 + 晴/多云天气
- **速率**：每游戏小时积累等效维D，日封顶 **~10µg**
- **实现**：每日结算前低频采样（isOutside + 游戏时间 + 天气接口）
- **玩法后果**：宅家党骨松、外出搜刮者安全——奖励游戏鼓励的行为

## 4. 功能设计（详细）

### 4.1 食物营养数据层

#### 4.1.1 数据表结构

每 100g 基准，Lua 表形式（`Nutri_DataLayer.lua`）：

```lua
FoodNutrition = {
    ["Base.CannedBolognese"] = { -- 罐头肉酱
        protein = 7.0,   -- g
        carbs   = 12.0,  -- g
        fat     = 3.5,   -- g
        sodium  = 480,   -- mg
        potassium = 250, -- mg
        calcium = 40,    -- mg
        iron    = 1.2,   -- mg
        vitA    = 15,    -- µg
        vitC    = 2,     -- mg
        vitD    = 0,     -- µg
        vitB1   = 0.05,  -- mg
    },
    -- ... 其余食物
}
```

#### 4.1.2 折算规则

- 按**实际食用重量**折算：食入 200g → 营养值 ×2.0。
- 未收录食物：按类别兜底映射（配置表 `FallbackCategory`：蔬菜/肉类/罐头/谷物...），保底不出现"无营养"。
- 第一版覆盖常见罐头、肉、蔬菜、水果、主食约 60-80 个高频食物，缺失走分类兜底。

#### 4.1.3 保质期与加工保留（腐败判定走原版接口：age vs offAge/offAgeMax）

**腐败三阶段：**

| 阶段 | 原版判定 | 宏量保留 | 维生素保留 | 吸收系数 | 中毒 |
|---|---|---|---|---|---|
| 新鲜 | age < offAge | 100% | 100% | ×1.0 | 原版 |
| 陈腐 | offAge ≤ age < offAgeMax | 70% | 50% | ×0.8 | 原版 |
| 变质 | age ≥ offAgeMax | 40% | 0% | ×0.5 | 原版概率 ×1.5 |

> 矿物质（钠/钾/钙/铁）三阶段保留率均为 100%：矿物质化学性质稳定，腐败不破坏之；变质的实际惩罚由吸收系数（×0.5）与中毒概率（×1.5）承担。

**加工路线保留率（真实营养学方案）：**

| 加工方式 | 效果 | 策略定位 |
|---|---|---|
| 冷冻 | 全营养保留 | 保留冠军；解冻后加速腐败，停电/迁移全完蛋 |
| 烹饪成品 | 宏量/矿物质 100% 保留，VC -30%（热敏损失），杀菌（中毒概率降低），吸收 +10% | 日常最优解 |
| 罐装 | VC 慢性损失 30-50%，保质期重置 | 碳水/蛋白/脂肪稳定，长期维C 会死 |
| 干燥（肉干） | 蛋白 90% 保留，VC 大损，保质期大延长 | 蛋白质储备手段 |

> 罐头维C 慢性死亡 + 冷冻全保留的对比，让"囤冻肉还是囤罐头"成为真实的生存策略选择。

### 4.2 摄入结算（进食）

- **事件**：`Events.OnEatFood`（B42 食物入口）。

```lua
-- 伪代码：进食 → 当日摄入累计
function Nutrition_OnEatFood(player, food, amount)
    local nutrition = Nutrition_GetPer100g(food)            -- 查表
    local factor    = amount / 100.0
    local spoil     = Nutrition_GetSpoilFactors(food)       -- 保质期保留系数，按营养类别取值（4.1.3）
    local absorb    = Nutrition_GetAbsorbFactor()           -- 档位吸收修正（4.4.5）
    DailyIntake[k] += nutrition[k] * factor * spoil[k] * absorb
end
```

- 当日摄入累计存于 `modData["Nutri.IntakeToday"]`，每日凌晨清零纳入历史。

### 4.3 消耗系统

#### 4.3.0 统一总公式

```
秒级消耗[宏量i] = 75 kcal/h × 活动倍率[4.3.2] × 环境修正[4.3.5]
                 × 属性修正[4.3.6, clamp 0.6~1.5]
                 × 强度配比[档位][i] ÷ 热价(i)        -- 碳水4 / 蛋白4 / 脂肪9

瞬时消耗[动作]  = 预算锚定值[4.3.3/4.3.4] × 属性修正（战斗类归重度）

固定周转[钙铁维生素] = DRI/24 × (1 + 受伤/生病叠加修正[4.3.8])
钠/钾             = DRI/24 × 活动倍率(钠钾列) × 温度修正
```

- **基础代谢锚点**：75 kcal/游戏小时（=1800/天），静息速率：碳水 8.4g/h、脂肪 3.3g/h、蛋白 2.8g/h。
- **关键校准性质**：静息日按 DRI 进食 ≈ 完美平衡；典型活跃日总耗 ~2400 kcal，必须比 DRI 多吃 30%——「活动决定消耗」的核心循环。
- clamp 只钳属性修正乘积，不钳活动×环境乘积（极端瞬态由原版耐力条先限制）。

#### 4.3.1 按秒结算（OnPlayerUpdate 累加器）

每秒执行一次（用累加器累积 ticks，不每 tick 全算）。

#### 4.3.2 活动倍率表 + 强度配比

| 状态 | 总倍率 | 钠钾倍率 | 判定 API |
|---|---|---|---|
| 睡眠 | 0.9 | 0.5 | isAsleep |
| 静立/室内整理 | 1.0 | 1.0 | !moving |
| 蹲走/潜行 | 1.4 | 1.3 | isCrouching |
| 步行 | 2.0 | 1.5 | isWalking |
| **劳作（timed action）** | 2.5 | 1.8 | 动作队列非空（排除进食/阅读） |
| 跑步 | 4.0 | 2.5 | isRunning |
| 冲刺 | 6.0 | 4.0 | isSprinting |

| 强度配比档 | 碳水 | 脂肪 | 蛋白 | 适用状态 |
|---|---|---|---|---|
| 标准 | 55% | 29% | 16% | 睡眠~劳作（镜像 DRI 能量结构） |
| 高强度 | 65% | 22% | 13% | 跑步 |
| 极高强度 | 72% | 16% | 12% | 冲刺 |

> 配比镜像 DRI 是刻意的：避免"静息脂肪供能 60%"之类的生理真实值导致脂肪结构性亏空、寒冷抗性 debuff 常驻。

**节奏抽查**：冲刺 10 游戏分钟 = 75 kcal 总耗，碳水 14g；重度搜刮日（40 次翻越/翻窗+攀爬）≈ 碳水 100-150g。

#### 4.3.3 瞬时动作消耗（预算锚定法）

瞬时动作动画是实时秒级，与游戏时钟不同步，**不与秒级模型换算**，按行为预算独立标定（重度搜刮日目标：碳水 100-150g ≈ DRI 的 40-60%）：

| 动作 | 碳水(g) | Na+K(mg) | 检测方式 |
|---|---|---|---|
| 翻越栅栏/矮墙 | 3 | 2 | 动作完成回调 |
| 攀爬绳索/床单绳 | 10 | 5 | 动作完成回调 |
| 翻窗进出 | 2 | 2 | 动作完成回调 |
| 楼层转换（每层） | 1 | 1 | `getZ()` 变化检测，负重 ×1.3 |

> 已删除：跳跃（原版无此动作）、重拳/撞门（砸门走 OnWeaponSwing 已覆盖，空手按轻量档）。

#### 4.3.4 战斗消耗（按武器重量分档，写实档）

每击（`OnWeaponSwing` + 武器重量，null 武器按轻量档）：

| 武器重量 | 碳水(g/击) | Na+K(mg/击) | 示例 |
|---|---|---|---|
| 空手 / < 1.5kg | 0.8 | 1 | 拳头、小刀、短棒 |
| 1.5 – 3kg | 1.5 | 2 | 球棒、手斧 |
| > 3kg | 3.0 | 4 | 大锤、消防斧 |

**预算验证**：中型遭遇战（5 僵尸 ≈ 35 击球棒）= 52g 碳水 ≈ 日 DRI 的 21%；大锤狂战日（80 击）≈ 240g ≈ 全天 DRI。压力来自累计而非单次，原版耐力条仍是战斗主约束。

#### 4.3.5 环境修正因子

| 修正项 | 触发条件 | 倍率 | 作用范围 |
|---|---|---|---|
| 负重 Lv1 | 占用率 > 70%（当前/最大容量） | ×1.15 | 仅移动/劳作状态 |
| 负重 Lv2 | > 90% | ×1.3 | 同上 |
| 负重 Lv3 | > 110% | ×1.5 | 同上 |
| 高温 | > 30°C | Na+K ×1.5 | 仅活动状态（出汗模型） |
| 低温 | < 5°C | 碳水 ×1.4 | **全天候含静息**（寒颤产热） |
| 生病 | 原版 sickness/fever > 阈值 | 总倍率 ×1.15 | 全天候 |

> 负重用相对占用率而非绝对 kg：自动随力量缩放，与原版超载判定同源。低温全天候意味着过冬静息日碳水 202g→283g，超过 DRI——过冬必须多吃主食。

#### 4.3.7 XP 驱动训练消耗

PZ 原版无训练动作，力量/体能 XP 来自战斗、冲刺、攀爬——消耗挂钩 XP 流：

| XP 来源 | 消耗 | 验证 |
|---|---|---|
| 每 10 点力量 XP | 1g 蛋白 | 一天 3 场遭遇战 ≈ 30g 蛋白 ≈ DRI 40%，战斗日蛋白需求 ~110g |
| 每 10 点体能 XP | 2g 碳水 + 50mg 钾 | 跑步日 300 XP = 60g 碳水 + 1.5g 钾 |

实现：包装 `AddXP` 接口，在经验入账时同步扣减。

#### 4.3.8 受伤/生病叠加修正

叠加在当前活动消耗上（人可以带伤走路，不设独立状态行）：

| 状态 | 修正 |
|---|---|
| 有未愈合伤口 | 蛋白 ×1.5、VC ×2.0（胶原合成）、铁 ×1.5（造血） |
| 生病（sickness/fever） | 总倍率 ×1.15（见 4.3.5） |

#### 4.3.9 体力双轨（原版耐力条 × 碳水储备）

原版耐力条 = 小时级资源（快耗快回），碳水储备 = 天级资源，两层通过透支加成耦合：

| 状态 | 触发 | 效果 |
|---|---|---|
| 糖原透支 | 耐力 < 30% | 秒级碳水消耗 ×1.5；挥击成本 ×1.5 |
| 力竭 | 耐力 < 10% | 碳水消耗 ×2.0；钠钾流失 ×1.5 |
| **乏力态** | 碳水储备 < 5% | 耐力恢复 -70%、移速 -20%（降级：疲劳+50%）、力量 XP -80%、无法冲刺 |

> 双轨状态（糖原透支/力竭/乏力）的效果一律进 4.4.5 钳制池：乏力态的 -70% 耐力恢复与 -80% XP 恰为各池下限，叠满即触底不再下探。
>
> 乏力的本质是"耐力条满了也没用"：睡一觉耐力恢复，但糖原空了，恢复速率被压到 -70%，且恢复过程本身还在烧碳水——恶性循环直到进食。原版耐力条机制完全不动。

### 4.4 营养储备与档位系统

#### 4.4.1 储备积分模型

```
储备[t] = clamp(储备[t-1] + 摄入 − 消耗, 0, 容量)
```

储备是净额的积分——**容量就是时间常数**，一套机制同时提供即时反馈（小容量）与长期平滑（大容量）。初始储备统一 75%（充足），"末日来临前吃得还行"。

#### 4.4.2 储备容量表

| 营养素 | 容量 | 语义 | 动态节奏 |
|---|---|---|---|
| 碳水 | 1.5天DRI（375g） | 糖原 | 断食1天→不足，2天→耗尽；大餐→盈余 buff |
| 钠 / 钾 | 各 1天DRI | 电解质池 | 高温冲刺日即可见失衡 |
| 蛋白 | 3天DRI（225g） | 可动用氨基酸池 | 断蛋白 3 天→肌肉分解启动 |
| 铁 | 14天DRI（210mg） | 铁储备 | 慢性贫血节奏 |
| VC | 5天DRI（500mg） | 组织VC | 坏血病节奏 |
| B1 | 7天DRI（8.4mg） | 硫胺素池 | 脚气病节奏 |
| VA / VD / 钙 | 各 30天DRI | 肝储备/骨密度 | 慢性病节奏 |
| 脂肪 | **不用储备** | — | 档位用 7 天净额平衡判定（储备=体脂=体重系统，另建会双计） |

#### 4.4.3 档位判定

| 档位 | 阈值（储备/容量） |
|---|---|
| 缺乏 | < 20% |
| 不足 | 20% – 50% |
| 充足 | 50% – 80% |
| 盈余 | > 80% |

- **滞回带 5pp**（80% 进、75% 出），防止战斗中临界值反复横跳导致 buff 闪烁。
- **脂肪档位**（7 天日均净额/DRI）：< -30% 缺乏 / -30~-5% 不足 / -5~+15% 充足 / > +15% 盈余。
- 钠钾档位取两者较低档。

#### 4.4.4 档位效果表

实现旋钮标注：①可靠（stats/XP 接口）②需验证（降级方案已备）③XP 获取率 ④自控系统

| 营养素 | 缺乏 <20% | 不足 20-50% | 充足 50-80% | 盈余 >80% |
|---|---|---|---|---|
| 碳水 | 耐力恢复-50%①<br>疲劳+30%①<br>移速-10%②（降级：疲劳+50%）<br>体能XP-50%③ | 耐力恢复-20%①<br>体能XP-30%③ | — | 耐力恢复+15%①<br>体能XP+30%③ |
| 钠钾（取低档） | 耐力恢复-40%①<br>攻速-15%②（降级：挥击耐力成本+20%）<br>体能XP-30%③ | 耐力恢复-15%①<br>攻速-5%②<br>体能XP-10%③ | — | 攻速+8%② |
| 蛋白 | 力量XP-50%③<br>愈合-50%①<br>**肌肉分解启动**（4.5） | 力量XP-30%③<br>愈合-20%① | 愈合+10%① | 力量XP+50%③（训练窗口） |
| 脂肪（7天净额） | 低温碳水消耗+25%②<br>饥饿感+30%②（降级：吸收-10%） | 耐力恢复-10%① | — | 耐力上限+10%① |
| VC | 愈合-30%①<br>免疫-30%④ | 愈合-10%① | 免疫+10%④ | 愈合+20%① |
| B1 | 疲劳+20%① | 疲劳+10%① | — | — |
| 铁 | 耐力恢复-15%① | — | — | — |
| VA | 夜间视野-10%②（降级：疲劳+10%①） | — | — | — |
| VD | 钙吸收-30%④ | 钙吸收-15%④ | 钙吸收+10%④ | — |
| 钙 | 愈合-10%① | — | 愈合+5%① | — |

> VD→钙吸收联动是亮点：VD 缺乏加速钙储备流失→推进骨松，完全走自控系统，且让日照通道有双重意义。

#### 4.4.5 叠加钳制与吸收修正

**跨营养素同效果类型求和后钳制**（疾病症状与双轨状态效果也进同池，见 4.7 / 4.3.9）：

| 效果类型 | 钳制区间 |
|---|---|
| 耐力恢复 | [-70%, +25%] |
| 耐力上限 | [-35%, +15%]（下限因贫血重度 -35% 放宽，贫血为唯一可触底疾病） |
| 疲劳积累 | [+60%, -20%] |
| 愈合 | [-70%, +40%] |
| XP 获取率 | [-80%, +80%]（下限因乏力态 -80% 放宽，恰为触底值） |
| 攻速/移速 | [-20%, +10%] |
| 钙吸收 | [-45%, +15%] |
| 视野 | [-10%]（疾病症状另计） |

**吸收修正**（档位作用于摄入侧）：缺乏 -15%、充足 +10%。刻意减半防死亡螺旋。

> 原 4.4.3「短期耐力修正表」整体作废，被本档位系统取代。

### 4.5 长期成长（力量/体能）

#### 4.5.1 成长公式

```
力量 XP 结算 = 原版 XP 流 × 蛋白档位修正 × 双门槛系数 − 肌肉分解扣减

双门槛系数（0~1 线性过渡）：
  1.0   蛋白储备 ≥ 50% 且 热量 7 天净额 ≥ -5%（吃好练好，全额成长）
  0     蛋白储备 < 20% 或 热量净额 < -20%（白练/伤身）
  中间  按两条件线性插值

体能 XP 结算 = 原版 XP 流 × 碳水档位修正 × 钠钾档位修正
               -- 修正值见 4.4.4 碳水/钠钾行的体能 XP 条目（镜像蛋白模式）：
               -- 碳水 缺乏-50% / 不足-30% / 盈余+30%；钠钾 缺乏-30% / 不足-10%
               -- 乘法叠加最坏 0.35 / 最好 1.30，均在 XP 钳制池内
```

#### 4.5.2 肌肉分解与阈值

| 项 | 数值 |
|---|---|
| 肌肉分解（蛋白储备 = 0） | 每日力量 XP **-15**（约 5 天掉 1 级，玩家有一周左右缓冲期自救） |
| 单日 XP 修正上限 | +150（防刷；扣减不设下限钳） |
| 体重 < 55kg | 力量 XP -50%（消瘦倾向，可与分解叠加） |

### 4.6 体重联动（完全接管模式）

#### 4.6.1 主公式

```
日体重增量 = 3天滚动热量净额 ÷ 7000 kcal/kg，钳制 ±0.25kg/日
```

- 7000 kcal/kg 接近真实值（7700），净 +500 kcal/天 ≈ 2kg/游戏月，一个月可感知。
- 3 天滚动均值防暴食暴瘦锯齿。

#### 4.6.2 四项配套责任

| 配套 | 方案 |
|---|---|
| 原版 calories 中和 | 每结算钉在维持值（~2000），防止双动 |
| 存档迁移 | 首次接管净额从 0 起算，体重起点不变，平滑无跳变 |
| 增减重构成 | 增重：蛋白储备≥50% 且训练刺激达标 → 70% 肌肉；否则 20%。减重：蛋白>20% → 脂肪 80%；蛋白耗尽 → 肌肉 60% |
| 体脂率派生量 | 内部估计值（初始按 trait，按构成比例更新），供肥胖症判定与 UI 展示，不碰原版接口 |

- Overweight/Underweight 等 trait 只影响初始体重，照常生效；代谢类 trait 干预列入实现期验证项。
- 旧表"速度因子"与">95kg 耐力惩罚"条目作废（后者并入肥胖症）。

### 4.7 营养疾病系统（8 种）

#### 4.7.1 统一疾病模型

```
触发：储备 < 20% 持续 N 天（消瘦/肥胖用组合条件）
升级：条件持续期间每 +5 天升 1 级（0潜伏→1轻度→2中度→3重度）
恢复：储备 > 50% 持续 3 天降 1 级
```

**康复期营养反馈**（吃好 buff / 吃差 debuff）：

```
恢复计数速率（基准 1.0，累计 3 点降 1 级）：
  × 1.5   当日该营养素摄入 ≥ 150% DRI → 「营养治疗」buff
  × 1.0   摄入 100-150%（标准康复）
  × 0.5   摄入 < 100% 但储备仍 >50% → 「迁延不愈」debuff
  清零     储备跌回 <20% → 「复发」：升级计时重启
```

UI 健康页在患病时显示"康复目标：VC ×1.5 = 150mg/天"式明确指令。

**节奏由容量参数驱动**（容量对齐节奏，调节奏不用改疾病表；基准为典型维持态 75% 储备完全断供起算，从满储备 100% 起算约慢 1/3）：

| 疾病 | 关联 | 75%→<20% | 触发 N | 发病总时长 | 到重度 |
|---|---|---|---|---|---|
| 电解质紊乱 | 钠或钾 | ~0.5 天 | 5 天 | **~6 天** | 21 天 |
| 消瘦 | 蛋白+热量 | ~1.5 天 | 7 天（且热量7天净额<-20%） | ~9 天 | 24 天 |
| 脚气病 | B1 | ~4 天 | 7 天 | 11 天 | 26 天 |
| 坏血病 | VC | ~3 天 | 10 天 | 13 天 | 28 天 |
| 贫血 | 铁 | ~8 天 | 7 天 | 15 天 | 30 天 |
| 夜盲症 | VA | ~16 天 | 10 天 | **26 天** | 42 天 |
| 骨质流失 | VD或钙 | ~16 天 | 14 天 | **30 天** | 46 天 |
| 肥胖症 | 脂肪+体重 | — | 14 天（脂肪盈余档持续 且 体重>90kg） | — | — |

#### 4.7.2 疾病清单与症状（按级 0→3 递进）

| 疾病 | 缺失营养 | 负面表现 | 状态量 |
|---|---|---|---|
| 坏血病 | VC | 伤口愈合 -20%/-40%/-60%；疲劳恢复 -10%/-25%/-40%；重度持续失血倾向 | `scurvy_level` |
| 贫血 | 铁 | 耐力上限 -10%/-20%/-35%；运动耗耐力 +15%/+30%/+50%；重度偶发眩晕（操作失灵 0.5s） | `anemia_level` |
| 电解质紊乱 | 钠/钾 | 耐力恢复 -20%/-40%/-60%；随机"抽搐"（1s 无法行动）；重度间歇意识模糊 | `electrolyte_level` |
| 消瘦 | 蛋白/热量 | 受伤 +10%/+20%/+35%；耐力恢复 -10%/-25%/-40%；重度负重大幅下降；**力量 XP -20%/-40%/-60%**（肌肉分解联动） | `wasting_level` |
| 夜盲症 | VA | 夜晚视野 -20%/-40%/-60%；光源半径 -20%/-35%/-50%；重度看不清 5 米外 | `nightblind_level` |
| 脚气病 | B1 | 奔跑后呼吸急促（疲劳值暴涨）；日常疲劳 +15%/+30%/+50%；重度走路都累 | `beriberi_level` |
| 骨质流失 | VD/钙 | 挥击小概率武器掉落；骨折愈合 -30%/-50%/-70%；重度摔落增加骨折率 | `osteoporosis_level` |
| 肥胖症（新） | 脂肪盈余+超重 | 移速 -5%/-10%/-15%（降级：疲劳+10/20/30%）；总倍率 ×1.05/1.1/1.15；耐力上限 -5%/-10%/-15%；恢复：脂肪净额回落至充足 且 体重<85kg 持续 7 天降 1 级 | `obesity_level` |

> 肥胖症的总倍率修正与 4.3.6 体重修正（+8%/超区间 10%）是两层设计：后者是即时体重负担，前者是长期代谢病，两者可叠加。

#### 4.7.3 叠加规则与实现

- 疾病症状与档位效果**按效果类型进同一钳制池**（4.4.5），疾病占大头、档位占小头。例：VC 缺乏档 愈合-30% + 坏血病中度 愈合-40% → 求和 -70% 触底，不再下叠。
- 疾病可多病并发，惩罚归一化累加防爆。
- 数值层：`stats:setEndurance()`、`setHealth()`、受击判定等原版接口。
- 视觉层：苍白肤色用身体外观接口调色；夜盲退化为"夜间屏幕蒙层"（若 B42 光照接口不可实现）。
- 交互层：抽搐/眩晕用操作锁定（短暂禁止输入），不新增与 Moodle 冲突的图标。

```
                                            │         ├─> 档位效果(钳制池) ─> 耐力/疲劳/愈合/XP率/吸收
活动/动作/战斗/XP(Exercise) ──属性/环境修正──> 当日消耗 ─┘         │
                                                                ▼
每日凌晨结算：历史入队(7天) ──> 脂肪档位/热量净额 ──> 成长双门槛 ──> Fitness/Strength XP
                                   │                        │
                                   └──> 3天热量滚动 ──> 体重接管 + 体脂率
                                                                │
                              疾病判定(储备阈值+持续计数) <──────┤
                                        │                       │
                                        └──> 症状(同池钳制) + 康复计数(营养驱动)
```

## 6. 测试策略

### 6.1 分层

| 层 | 方式 | 工具 |
|---|---|---|
| 逻辑单元测试 | 储备积分/档位/疾病阈值/消耗公式/康复计数写成纯函数 + 独立断言脚本 | luajit（PZ 同款 Lua 5.1 JIT） |

| ModData 持久化 | 吃指定食物→读档验证数值保持 | console + 存档检查 |

### 6.2 关键验证用例

1. **参考饮食落点检查**（数据表平衡的客观标尺）：纯罐头流必须缺 VC/VD/钙；混合流（沙丁鱼+面包+土豆+卷心菜+胡萝卜+黄油）大部分达标；农场流蛋白偏紧（打猎压力）。
2. 摄入结算：吃 100g 罐头豆 → 营养值折算正确；陈腐期食物 → 宏量 ×0.7、维C ×0.5、吸收 ×0.8。
3. 运动消耗：冲刺 30s → 碳水按 6.0×极高配比扣减；翻越 → 瞬时 -3g；劳作 timed action → 2.5×。
4. 储备动态：静息日吃 DRI → 储备稳态；断碳水 2 天 → 乏力态；大餐后 → 盈余 buff + 滞回不闪。
5. 档位效果：碳水缺乏 → 耐力恢复 -50% 生效且与疾病同池钳制不爆。
6. 长期成长：蛋白充足+热量盈余+训练 → 力量正增长；蛋白储备归零 → 每日 -15 XP（5 天 1 级）。
7. 疾病触发/恢复：断 VC → 第 3 天入缺乏档、第 13 天坏血病；康复期吃 150% DRI → 计数 ×1.5 加速；跌回 <20% → 复发清零（含读档持续）。
8. 体重接管：热量盈余 3 天 → 体重按 ÷7000 递增；原版 calories 被钉维持值无双动；存档迁移无跳变。
9. 并发防爆：8 病全触发 → 惩罚归一化，无负数/NaN。
10. 性能：1 游戏小时 CPU 增量在阈值内（每秒结算用累加器，日照低频采样）。

## 9. 验收标准

1. **动态平衡**：吃多/吃少/运动多/运动少四种组合下，储备档位出现可感知差异；活跃日不吃 extra 就入不足档（消耗≈摄入循环成立）。
2. **档位反馈**：盈余给 buff、缺乏出 debuff，滞回无闪烁，11 项营养素并发效果钳制不爆。
3. **疾病全链路**：8 种疾病按容量节奏触发、演进、恢复；康复期吃好加速/吃差迁延/复发清零可复现（含读档）。
4. **成长闭环**：蛋白+热量双门槛、XP 驱动消耗、肌肉分解全部生效；原版 Fitness 封顶逻辑不被破坏。
5. **体重接管**：热量净额驱动体重变化，原版 calories 无双动，存档迁移平滑，体脂率随构成更新。
6. **保质期策略**：罐头流维C 慢性死亡、冷冻全保留但解冻加速腐败，"囤冻肉 vs 囤罐头"策略成立。
7. **UI**：面板正确展示储备/档位/趋势/疾病/康复目标，风格与原版一致无违和。
8. **数据驱动**：改 `Nutri_Config.lua` 即可平衡（调节奏=调容量），无需改逻辑代码。
