## 1. 项目概述

在《僵尸毁灭工程》（Project Zomboid）中制作一个**营养仿真 MOD**，把原版"碳水/蛋白质/脂肪/卡路里"四维、只影响体重的营养模型，升级为**多维度营养素仿真系统**，让"吃什么、吃多少、怎么运动"真正决定角色的短期状态与长期成长。

### 1.1 核心目标

1. **食物营养细化**：在蛋白质、碳水、脂肪之上，增加无机盐（钠/钾/钙/铁）与维生素（A/C/D/B族）等大类。
2. **人物运动消耗**：跑步/步行/蹲下/潜行/战斗/翻越/爬楼等动作消耗营养，并叠加负重、温度等环境修正。
3. **体力耐力成长**：长期营养盈余/亏空 + 运动量，决定体能（Fitness）与力量（Strength）经验的增长或下降，并联动体重。
4. **营养疾病**：长期失衡触发 7 种末日高发营养疾病，每种有触发条件、阶段症状、恢复机制。
5. **UI 展示**：营养面板 + 7 天趋势 + 疾病详情，风格完全对齐原版（Vanilla-Native）。

### 1.2 设计原则

- **单机优先**：逻辑以服务端/共享模块为主，预留多人接口，第一版不保证联机。
- **数据驱动**：食物营养表、消耗倍率、疾病参数、评分曲线全部集中配置，调参不动代码。
- **模块化**：数据层/营养/历史/疾病/运动/成长/UI 各自独立，职责单一、可独立测试。
- **对齐原版**：体重、Fitness 经验封顶等原生机制完全复用，不重复造轮子、不破坏原版平衡边界。

## 4. 功能设计（详细）

### 4.1 食物营养数据层

#### 4.1.1 数据分层策略（宏量复用原版 + 微量自建）

PZ 原版每个食物项已有 **4 个宏量营养素**定义在脚本中，可运行时直接读取，**无需手动维护**。MOD 只需自建原版缺失的**微量营养素**数据。

| 层级 | 营养素 | 数据来源 | 维护方式 |
|---|---|---|---|
| 宏量（原版已有） | 卡路里 / 碳水 / 蛋白质 / 脂肪 | PZ 食物脚本字段 `Calories` / `Carbohydrates` / `Proteins` / `Lipids` | 运行时 `food:getCalories()` 等接口读取 |
| 微量（MOD 自建） | 钠 / 钾 / 钙 / 铁 / 维生素 A/C/D/B1 | 真实营养数据库（见 4.1.4） | `Nutri_DataLayer.lua` 手动维护 |

**原版宏量读取接口**（PZ `Food` 类）：

```lua
food:getCalories()       -- 总卡路里（kcal）
food:getCarbohydrates()  -- 总碳水（g）
food:getProteins()       -- 总蛋白质（g）
food:getLipids()         -- 总脂肪（g）
item:getWeight()         -- 物品重量（kg）
```

#### 4.1.2 数据表结构（仅存微量营养素）

每 100g 基准，Lua 表形式（`Nutri_DataLayer.lua`）：

```lua
-- 食物微量营养表（每100g基准，宏量从原版读取）
FoodMicronutrients = {
    ["Base.TinnedBeans"] = { -- 罐头豆（宏量：Calories=170, Carbs=33, Protein=7, Fat=1）
        sodium    = 230,   -- mg
        potassium = 410,   -- mg
        calcium   = 58,    -- mg
        iron      = 2.3,   -- mg
        vitA      = 0,     -- µg
        vitC      = 6,     -- mg
        vitD      = 0,     -- µg
        vitB1     = 0.06,  -- mg
    },
    ["Base.Rice"] = { -- 生米
        sodium    = 5, potassium = 115, calcium = 28, iron = 0.8,
        vitA = 0, vitC = 0, vitD = 0, vitB1 = 0.58,
    },
    -- ... 其余食物
}
```

#### 4.1.3 单位换算与折算规则

- **宏量换算（原版总量 → 每 100g）**：
  ```
  每100g值 = 原版总量 × 100 / (item:getWeight() × 1000)
  ```
  例：罐头豆重 0.8kg，蛋白质 7g → 每100g蛋白质 = 7 × 100 / 800 = 0.875g
- **食用折算**：食入 200g → 营养值 ×2.0。
- **烹饪不改变营养表**（第一版简化；食物煮烂流失 VC 属后续增强项）。
- **未收录食物**：按类别兜底映射（配置表 `FallbackCategory`：蔬菜/肉类/罐头/谷物...），保底不出现"无营养"。

#### 4.1.4 微量营养素数据来源

原版没有的无机盐和维生素数据，从以下权威数据库查询，统一到**每 100g 基准**：

| 数据源 | 网址 | 特点 |
|---|---|---|
| **USDA FoodData Central** | https://fdc.nal.usda.gov/ | 美国农业部官方，最全，提供 **API**，可程序化批量查询 |
| **中国食物成分表** | https://nlc.chinanutri.cn/ | 中国疾控中心营养所，中文权威数据 |
| **OpenFoodFacts** | https://world.openfoodfacts.org/ | 开源众包，支持中文食品，有 API |
| **911查询营养成分** | https://yingyang.911cha.com/ | 中文界面，快速查常见食物 |

**单位转换注意**：
- 维生素 A：USDA 有时用 IU → 1 IU = 0.3 µg 视黄醇
- 维生素 D：USDA 有时用 IU → 1 IU = 0.025 µg
- 所有数据统一到"每 100g"基准

#### 4.1.5 数据录入范围

- 第一版覆盖：常见罐头、肉、蔬菜、水果、主食（约 60-80 个高频食物）。
- 缺失食物走分类兜底，后续按需补齐。
- 宏量营养素自动从原版获取，无需录入。

### 4.2 摄入结算（进食）

- **事件**：`Events.OnEatFood`（B42 食物入口）。

```lua
-- 伪代码：进食 → 当日摄入累计
function Nutrition_OnEatFood(player, food, amount)
    local factor = amount / 100.0                       -- 重量折算

    -- 宏量营养素：从原版 Food 接口读取并换算为每100g
    local w = food:getWeight() * 1000                   -- 物品总重（g）
    local per100 = 100 / w
    DailyIntake.calories += food:getCalories() * per100 * factor
    DailyIntake.carbs    += food:getCarbohydrates() * per100 * factor
    DailyIntake.protein  += food:getProteins() * per100 * factor
    DailyIntake.fat      += food:getLipids() * per100 * factor

    -- 微量营养素：从自建数据表读取
    local micro = FoodMicronutrients[food:getFullType()] or FallbackCategory[food]
    for k, v in pairs(micro) do
        DailyIntake[k] += v * factor
    end
end
```

- 当日摄入累计存于 `modData["Nutri.IntakeToday"]`，每日凌晨清零纳入历史。

### 4.3 运动消耗系统

#### 4.3.1 按秒结算（OnPlayerUpdate 累加器）

每秒执行一次（用累加器累积 ticks，不每 tick 全算）。每种动作有独立**营养消耗向量**：

| 动作状态 | 判定 API | 碳水(g/s) | 无机盐(mg/s) | 说明 |
|---|---|---|---|---|
| 休息/站立 | `isRunning()==false && !isWalking()` | 基础值 | 微量 | 基础代谢 |
| 蹲走/潜行 | `isCrouching()` | 基础×1.4 | 基础×1.2 | 肌肉持续紧张 |
| 步行 | `isWalking()` | 基础×2 | 基础×1.5 | — |
| 跑步 | `isRunning()` | 基础×4 | 基础×2.5 | 出汗排钠钾 |
| 冲刺 | `isSprinting()` | 基础×7 | 基础×4 | 短暂缺氧 |

#### 4.3.2 瞬时动作结算（动作完成一次扣一次）

触发：`OnWeaponSwing` / 动作监听（timed action 完成回调）。

| 动作 | 碳水(g) | 无机盐(mg) | 额外效果 |
|---|---|---|---|
| 翻越栅栏/矮墙 | 30 | 8 | 碳水储备过低时落地踉跄 |
| 攀爬绳索 | 45 | 10 | — |
| 翻窗进出 | 20 | 6 | — |
| 上下楼梯 | 12 | 3 | 带负重 ×1.3（"爬楼费劲"） |
| 跳跃 | 8 | 2 | 连续跳跃二次结算 |
| 重拳/撞门 | 20 | 5 | 空手破门更费力 |
| 挥击（按武器重量分档） | 见 4.3.3 | — | — |

#### 4.3.3 战斗消耗（按武器重量分档）

每击（`OnWeaponSwing` + `getPrimaryHandItem():getWeight()`）：

| 武器重量 | 每击碳水(g) | 每击无机盐(mg) | 示例 |
|---|---|---|---|
| < 1.5kg | 5 | 1 | 小刀、短棒 |
| 1.5 – 3kg | 12 | 3 | 球棒、斧头 |
| > 3kg | 25 | 6 | 大锤、消防斧 |

#### 4.3.4 环境修正因子（乘在当前档位值上）

- **负重修正**：总重 > 20/35/50kg → ×1.15 / ×1.3 / ×1.5
- **温度修正**：>30°C 无机盐 ×1.5（出汗）；<5°C 碳水 ×1.4（产热）
- 第一版不做湿度与风速。

### 4.4 长期均值与体力耐力成长

#### 4.4.1 每日结算与 7 天滚动窗口

- 存储：`modData["Nutri.History"] = { {day, 各营养净额}, ... }`（最近 7 天）。
- 每日净额 = 当日摄入 −（基础代谢 + 运动消耗 + 瞬时动作）。
- **在每日凌晨 0 点结算**（基于游戏时钟 / `OnGameDay` 类事件），非实时写队列。

#### 4.4.2 评分归一化

- 每类营养：`d_i = clamp(当日净额 / 当日需求, -1, +1)`，`d_i ∈ [-1,1]`。
- 7 天均值 `avg(d_i) ` → "营养满足度" 用于长期成长。

#### 4.4.3 短期体力耐力（小时级，当天/近 2 天）

| 条件 | 效果（参数可调） |
|---|---|
| 近 2 天净额 > 0 | 耐力上限 +5%，恢复 ×1.1 |
| 近 2 天净额 ≈ 0 | 无修正 |
| 近 2 天净额 < 0 | 上限 -10%，恢复 ×0.85 |
| 当天碳水严重亏空（d < -0.6） | 耐力恢复冻结（饿着跑不动） |

> 与疾病系统叠加（见 4.6），采用归一化防爆。

#### 4.4.4 长期成长（周级）

**核心生理逻辑**：现实中力量增长需要三个条件同时满足——**训练刺激 + 蛋白质盈余 + 热量盈余**。缺一则不长肌肉（甚至分解）。

```
┌─────────────────────────────────────────────────────────┐
│  力量增长三重门（全部满足才正增长）                        │
│                                                          │
│  ① 训练刺激：当日训练量 > 阈值（抗阻训练信号）            │
│  ② 蛋白盈余：7天蛋白均值 > DRI（肌肉合成原料）            │
│  ③ 热量盈余：7天热量均值 > 消耗（合成能量来源）           │
│                                                          │
│  三者缺一 → 力量不增长（甚至负增长，分解肌肉供能）        │
└─────────────────────────────────────────────────────────┘
```

##### 训练刺激 S 的构成

PZ 原版已有 **Exercise 锻炼系统**（深蹲/俯卧撑/仰卧起坐/波比跳/杠铃/哑铃），加上末日生存中的日常活动，共同构成训练刺激。

| 训练来源 | 具体动作 | 力量刺激 | 体能刺激 | 说明 |
|---|---|---|---|---|
| **原版锻炼** | 俯卧撑 / 哑铃推举 / 杠铃弯举 / 哑铃弯举 | ★★★★★ | ★ | 纯抗阻，力量主力 |
| **原版锻炼** | 波比跳 | ★★★ | ★★★★ | 全身复合，力量+体能 |
| **原版锻炼** | 深蹲 | ★ | ★★★★ | 下肢力量为主，体能提升大 |
| **原版锻炼** | 仰卧起坐 | ★ | ★★ | 核心，体能为辅 |
| **生存活动** | 挥武器（按重量分档） | ★★★~★★★★ | ★★ | 近战 = 抗阻训练 |
| **生存活动** | 翻越栅栏/爬窗/攀爬 | ★★ | ★★★ | 自重抗阻 + 心肺 |
| **生存活动** | 跑步/冲刺 | ★ | ★★★★★ | 心肺为主，少量下肢力量 |
| **生存活动** | 负重搬运 | ★★★ | ★★ | 负重行走 = 抗阻 |

**原版锻炼系统已有机制**（不重复造轮子，叠加营养调制）：
- 每种锻炼直接给 Strength/Fitness XP（如俯卧撑 6 XP/次，深蹲 4 Fitness XP/次）
- 原版已有 Protein Boost：蛋白质在 50~300 时力量 XP ×1.5
- 肌肉拉伤（Muscle Strain）会降低近战伤害和攻击速度
- Regularity 规律性减少拉伤

**MOD 的训练刺激 S 计算**（叠加在原版 XP 之上，作为营养调制系数）：

```
训练刺激 S = (主动锻炼量 × 权重_锻炼 + 生存活动量 × 权重_活动) / 阈值

主动锻炼量 = Σ(每种锻炼次数 × 该锻炼刺激系数)
生存活动量 = 跑步秒数×0.3 + 挥击次数×武器系数 + 翻越次数×2 + 负重搬运秒数×0.5

S = clamp(S, 0, 1.5)
```

> 原版锻炼系统直接给 XP，MOD 的 S 值作为**营养调制层**：决定原版 XP 是被放大还是被抑制。

##### 经验流公式

```
训练刺激 S = clamp(当日训练量 / 阈值, 0, 1.5)        -- 0~1.5
蛋白盈余 P = max(0, 7天蛋白均值 - DRI蛋白) / DRI蛋白   -- 0~1+
热量盈余 E = max(0, 7天热量均值 - 日消耗) / 日消耗     -- 0~1+

力量经验流 ΔStrength = S × min(P, 1) × (0.5 + 0.5×min(E,1)) × 系数
体能经验流 ΔFitness  = S × 营养综合满足度 × 系数
```

**关键规则**：
- **蛋白是硬门槛**：`P = 0` 时 `ΔStrength = 0`（练再多也不长，甚至负增长）
- **热量是放大器**：`E = 0` 时 `ΔStrength` 减半；盈余越大增长越快，但盈余过量转化为脂肪
- **训练是触发器**：`S = 0` 时不增长（光吃不练不长肌肉，只长胖）

| 训练量 S | 蛋白 P | 热量 E | 力量结果 | 说明 |
|---|---|---|---|---|
| 高 | 盈余 | 盈余 | **快速增长** | 理想增肌状态 |
| 高 | 盈余 | 平衡 | 中等增长 | 蛋白够但能量不足，增长受限 |
| 高 | 不足 | 盈余 | 不增长/负增长 | 原料不足，训练反而分解肌肉 |
| 高 | 不足 | 亏空 | 快速负增长 | "练伤自己"，肌肉流失 |
| 低 | 盈余 | 盈余 | 缓慢增长/长胖 | 缺训练信号，蛋白转化为脂肪而非肌肉 |
| 低 | 不足 | 亏空 | 缓慢负增长 | "坐吃山空"，肌肉萎缩 |

**"多吃长力量"的正确实现**：
- ✅ 吃够蛋白质（>DRI 75g/天）+ 有热量盈余 + 有训练 → 力量增长
- ❌ 只多吃碳水/脂肪但蛋白不足 → 不长力量，只长胖
- ❌ 蛋白够但不运动 → 不长力量，多余蛋白转化为脂肪或排出
- ❌ 运动但蛋白不够 → 力量下降（肌肉分解供能）

- 实现：在原版 XP 基础上叠加营养调制系数，`player:getXp():AddXP(Perks.Strength, 原版XP × 营养调制系数)`，营养调制系数 = S × min(P,1) × (0.5+0.5×min(E,1))。
- 钳制：单日经验 delta 上限防刷；耐力上限修正 clamp ±20%；多病并发归一化。

### 4.5 体重联动（第一版）

| 触发条件（7 天均值） | 体重变化 | 副作用 |
|---|---|---|
| 热量盈余 + 运动量低 | +0.1kg/周期 | 负重上限增、跑步消耗升 |
| 热量盈余 + 运动量高 | 稳定，力量优先（肌肉） | — |
| 热量亏空 + 运动量高 | -0.15kg/周期（先脂肪后肌肉） | 触发消瘦阈值 → 消瘦病 |
| 热量亏空 + 运动量低 | 缓慢掉重 | 同上 |

- 实现方式：**调用原版营养/体重接口**（`player:getNutrition()` 相关），叠加速度因子，不接管原版权重计算。
- 体重阈值联动：<55kg 加快力量流失；>95kg 耐力恢复惩罚（肥胖负担）。
- **肌肉 vs 脂肪**：热量盈余时，若蛋白质充足且有训练刺激 → 盈余转化为肌肉（力量增长，体重稳定）；若蛋白质不足或无训练 → 盈余转化为脂肪（体重增加，力量不增长）。详见 4.4.4 力量三重门。
- 原版/Fitness 经验封顶 trait 逻辑**保持原样生效**，我们不绕过。

### 4.6 营养疾病系统

#### 4.6.1 疾病模型（统一表驱动）

- 触发：某营养素**7 天均值 < 阈值连续 N 天** → 进入"潜伏 → 轻度 → 中度 → 重度"（0-3 级）。
- 恢复：补充达标连续 M 天 → 逐级下降。
- 疾病可多病并发，惩罚**归一化累加**（见 4.4.4），防止属性爆负。

#### 4.6.2 疾病清单与负面表现

| 疾病 | 缺失营养 | 负面表现（按阶段递进 0→3） | 状态量 |
|---|---|---|---|
| 坏血病 | 维生素C | 伤口愈合 -20%/-40%/-60%；疲劳恢复 -10%/-25%/-40%；重度持续失血倾向 | `scurvy_level` |
| 贫血 | 铁 | 耐力上限 -10%/-20%/-35%；运动耗耐力 +15%/+30%/+50%；重度偶发眩晕（操作失灵 0.5s） | `anemia_level` |
| 电解质紊乱 | 钠/钾 | 耐力恢复 -20%/-40%/-60%；随机"抽搐"（1s 无法行动）；重度间歇意识模糊（摇晃+控制倒置） | `electrolyte_level` |
| 消瘦 | 蛋白/热量 | 皮肤苍白；受伤 +10%/+20%/+35%；耐力恢复 -10%/-25%/-40%；重度负重大幅下降 | `wasting_level` |
| 夜盲症 | 维生素A | 夜晚视野 -20%/-40%/-60%；光源半径 -20%/-35%/-50%；重度看不清 5 米外 | `nightblind_level` |
| 脚气病 | 维生素B1 | 奔跑后呼吸急促（疲劳值暴涨）；日常疲劳 +15%/+30%/+50%；重度走路都累 | `beriberi_level` |
| 骨质流失 | 维生素D/钙 | 挥击小概率武器掉落；骨折愈合 -30%/-50%/-70%；重度摔落增加骨折率 | `osteoporosis_level` |

#### 4.6.3 症状实现与视觉

- 数值层：修改 `stats:setEndurance()`、`setHealth()`、受击判定、负重上限等原版接口。
- 视觉层：苍白肤色用身体外观接口调色；夜盲退化为"夜间屏幕蒙层"（若 B42 光照接口不可实现）。
- 交互层：抽搐/眩晕用操作锁定（短暂禁止输入），不新增与 Moodle 冲突的新心情图标。

### 10.4 模拟引擎核心流程

```lua
function Simulate(config)
    local history = {}
    local diseaseStates = InitDiseases()
    local xp = { fitness = 0, strength = 0 }

    for day = 1, config.days do
        -- 1. 计算当日摄入
        local intake = CalcDailyIntake(config.diet)

        -- 2. 计算当日消耗（含动作消耗 + 瞬时动作 + 环境修正）
        local consumption = CalcDailyConsumption(config.activity, config.temperature, config.carryWeight)

        -- 3. 计算当日净额
        local net = {}
        for k, v in pairs(intake) do
            net[k] = v - (consumption[k] or 0)
        end

        -- 4. 归一化评分
        local score = NormalizeScore(net, DRI)

        -- 5. 更新 7 天滚动均值
        history[day] = net
        local avg7 = Calc7DayAvg(history, day)

        -- 6. 疾病判定
        UpdateDiseases(diseaseStates, avg7)

        -- 7. 成长判定（力量三重门）
        --    S = 训练刺激（主动锻炼 + 生存活动）
        --    P = 蛋白盈余（7天均值 > DRI）
        --    E = 热量盈余（7天均值 > 消耗）
        local growth = CalcGrowth(avg7, config.activity, DRI)
        xp.fitness  = xp.fitness + growth.fitness
        xp.strength = xp.strength + growth.strength

        -- 8. 体重估算
        local weightDelta = CalcWeightDelta(net, config.activity)
    end

    return {
        history = history,
        diseaseStates = diseaseStates,
        xp = xp,
        finalScore = avg7,
    }
end
```

### 10.5 消耗反推校准（核心功能）

工具提供**自动校准**模式：给定目标饮食方案，反推消耗基础值使每日净额接近平衡。

```lua
-- 目标：让典型饮食的每日净额 d_i ∈ [-0.1, +0.1]
function AutoTuneConsumption(diet, targetDRI, activityProfile)
    local baseCarbs = 0.001  -- 初始猜测
    local step = 0.0001

    for i = 1, 100 do
        local intake = CalcDailyIntake(diet)
        local consumption = CalcDailyConsumption(activityProfile, baseCarbs)
        local netCarbs = intake.carbs - consumption.carbs
        local d = netCarbs / targetDRI.carbs

        if math.abs(d) < 0.1 then break end
        -- 摄入 > 消耗 → 提高基础消耗；反之降低
        baseCarbs = baseCarbs + (d > 0 and step or -step)
    end

    return baseCarbs  -- 输出平衡后的碳水基础消耗值
end
```
