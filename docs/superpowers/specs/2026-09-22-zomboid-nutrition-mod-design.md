- 日期：2026-09-22

## 1. 项目概述

在《僵尸毁灭工程》（Project Zomboid）中制作一个**营养仿真 MOD**，把原版"碳水/蛋白质/脂肪/卡路里"四维、只影响体重的营养模型，升级为**多维度营养素仿真系统**，让"吃什么、吃多少、怎么运动"真正决定角色的短期状态与长期成长。

### 1.1 核心目标

1. **食物营养细化**：在蛋白质、碳水、脂肪之上，增加无机盐（钠/钾/钙/铁）与维生素（A/C/D/B族）等大类。
2. **人物运动消耗**：跑步/步行/蹲下/潜行/战斗/翻越/爬楼等动作消耗营养，并叠加负重、温度等环境修正。
3. **体力耐力成长**：长期营养盈余/亏空 + 运动量，决定体能（Fitness）与力量（Strength）经验的增长或下降，并联动体重。
4. **营养疾病**：长期失衡触发 5 种末日高发营养疾病（坏血病/贫血/电解质紊乱/消瘦/夜盲症），每种有触发条件、阶段症状、恢复机制。脚气病与骨质流失纳入 v2。
5. **UI 展示**：营养面板 + 7 天趋势 + 疾病详情，风格完全对齐原版（Vanilla-Native）。

### 1.2 设计原则

- **单机优先**：逻辑以服务端/共享模块为主，预留多人接口，第一版不保证联机。
- **数据驱动**：食物营养表、消耗倍率、疾病参数、评分曲线全部集中配置，调参不动代码。
- **模块化**：数据层/营养/历史/疾病/运动/成长/UI 各自独立，职责单一、可独立测试。
- **对齐原版**：体重、Fitness 经验封顶等原生机制完全复用，不重复造轮子、不破坏原版平衡边界。

## 4. 功能设计（详细）

### 4.1 食物营养数据层

#### 4.1.1 数据表结构

每 100g 基准，Lua 表形式（`Nutri_DataLayer.lua`）：

```lua
-- 食物营养表（每100g基准）
FoodNutrition = {
    ["Base.CannedBolognese"] = { -- 罐头肉酱
        protein = 7.0,   -- g
        carbs   = 12.0,  -- g
        fat     = 3.5,   -- g
        sodium  = 480,   -- mg 无机盐细项
        potassium = 250, -- mg
        calcium = 40,    -- mg
        iron    = 1.2,   -- mg
        vitA    = 15,    -- µg
        vitC    = 2,     -- mg
        vitD    = 0,     -- µg
        vitB1   = 0.05,  -- mg
    },
    -- ... 其余食物
}
```

#### 4.1.2 折算规则

- 按**实际食用重量**折算：食入 200g → 营养值 ×2.0。
- 烹饪不改变营养表（第一版简化；食物煮烂流失 VC 属后续增强项）。
- 未收录食物：按类别兜底映射（配置表 `FallbackCategory`：蔬菜/肉类/罐头/谷物...），保底不出现"无营养"。

#### 4.1.3 数据录入范围

- 第一版覆盖：常见罐头、肉、蔬菜、水果、主食（约 60-80 个高频食物）。
- 缺失食物走分类兜底，后续按需补齐。

### 4.2 摄入结算（进食）

PZ Build 42 **不存在 `OnEatFood` Lua 事件**（已通过 LuaDocs 42.20.3 完整事件列表确认）。进食跟踪采用 **Hook 原版 `ISEatFoodAction`** 的方式，在食物被消耗时读取类型与食用量。

```lua
-- 在 client 侧 Hook 原版进食 Timed Action 的 perform 方法
local originalPerform = ISEatFoodAction.perform
function ISEatFoodAction:perform()
    originalPerform(self)
    -- self.character 是进食玩家，self.item 是被吃的食物
    Nutrition_OnEatFood(self.character, self.item)
end

-- 结算：进食 → 当日摄入累计
function Nutrition_OnEatFood(player, food)
    local nutrition = Nutrition_GetPer100g(food)              -- 查表
    local factor = math.abs(food:getHungChange()) / 100.0       -- 按原版饥饿变化量折算食用比例
    DailyIntake[营养大类] += nutrition[k] * factor               -- 写入当日累计
end
```

- 当日摄入累计存于 `modData["Nutri.IntakeToday"]`，每日凌晨清零纳入历史。
- 兼容性注意：若其他 MOD 也修改了 `ISEatFoodAction.perform`，需用链式 Hook 而非直接覆盖（保存原函数引用再调用）。

### 4.3 运动消耗系统

#### 4.3.1 按秒结算（OnPlayerUpdate 累加器）

每秒执行一次（用累加器累积 ticks，不每 tick 全算）。每种动作有独立**营养消耗向量**：

| 动作状态 | 判定 API | 碳水(g/s) | 无机盐(mg/s) | 说明 |
|---|---|---|---|---|
| 休息/站立 | `isRunning()==false && !isWalking()` | 基础值 | 微量 | 基础代谢 |
| 蹲走/潜行 | `isCrouching()` | 基础×1.4 | 基础×1.2 | 肌肉持续紧张 |
| 步行 | `isWalking()` | 基础×2 | 基础×1.5 | — |
| 跑步 | `isRunning()` | 基础×4 | 基础×2.5 | 出汗排钠钾 |
| 冲刺 | `isSprinting()` | 基础×7 | 基础×4 | 短暂缺氧 |

> **方法签名确认**：`isWalking()` 已在 IsoPlayer JavaDoc 确认存在；`isRunning()`/`isSprinting()`/`isCrouching()` 为 PZ 标准 API（分布于 IsoGameCharacter / IsoPlayer 继承链），实现前须用 `dumpAPI` 或 JavaDoc 核对精确名称与参数。若某方法不可用，降级方案：用 `canSprint()` + `getBeenSprintingFor()`（已确认存在于 IsoGameCharacter）组合判定冲刺状态。

#### 4.3.2 瞬时动作结算（动作完成一次扣一次）

触发：`OnWeaponSwing` / 动作监听（timed action 完成回调）。

| 动作 | 碳水(g) | 无机盐(mg) | 额外效果 |
|---|---|---|---|
| 翻越栅栏/矮墙 | 30 | 8 | 碳水储备过低时落地踉跄 |
| 攀爬绳索 | 45 | 10 | — |
| 翻窗进出 | 20 | 6 | — |
| 上下楼梯 | 12 | 3 | 带负重 ×1.3（"爬楼费劲"） |
| 跳跃 | 8 | 2 | 连续跳跃二次结算 |
| 重拳/撞门 | 20 | 5 | 空手破门更费力 |
| 挥击（按武器重量分档） | 见 4.3.3 | — | — |

#### 4.3.3 战斗消耗（按武器重量分档）

每击（`OnWeaponSwing` + `getPrimaryHandItem():getWeight()`）：

| 武器重量 | 每击碳水(g) | 每击无机盐(mg) | 示例 |
|---|---|---|---|
| < 1.5kg | 5 | 1 | 小刀、短棒 |
| 1.5 – 3kg | 12 | 3 | 球棒、斧头 |
| > 3kg | 25 | 6 | 大锤、消防斧 |

#### 4.3.4 环境修正因子（乘在当前档位值上）

- **负重修正**：总重 > 20/35/50kg → ×1.15 / ×1.3 / ×1.5
- **温度修正**：>30°C 无机盐 ×1.5（出汗）；<5°C 碳水 ×1.4（产热）
- 第一版不做湿度与风速。

### 4.4 长期均值与体力耐力成长

#### 4.4.1 每日结算与 7 天滚动窗口

- 存储：`modData["Nutri.History"] = { {day, 各营养净额}, ... }`（最近 7 天）。
- 每日净额 = 当日摄入 −（基础代谢 + 运动消耗 + 瞬时动作）。
- **在每日凌晨 0 点结算**（基于游戏时钟 / `OnGameDay` 类事件），非实时写队列。

#### 4.4.2 评分归一化

- 每类营养：`d_i = clamp(当日净额 / 当日需求, -1, +1)`，`d_i ∈ [-1,1]`。
- 7 天均值 `avg(d_i) ` → "营养满足度" 用于长期成长。

#### 4.4.3 短期体力耐力（小时级，当天/近 2 天）

| 条件 | 效果（参数可调） |
|---|---|
| 近 2 天净额 > 0 | 耐力上限 +5%，恢复 ×1.1 |
| 近 2 天净额 ≈ 0 | 无修正 |
| 近 2 天净额 < 0 | 上限 -10%，恢复 ×0.85 |
| 当天碳水严重亏空（d < -0.6） | 耐力恢复冻结（饿着跑不动） |

> 与疾病系统叠加（见 4.6），采用归一化防爆。

#### 4.4.4 长期成长（周级）

```
每日经验流 = 训练刺激（当日运动量，0~1）× 营养满足度（蛋白+碳水7天均值，-1~1）
```

| 运动量 | 营养状况 | 结果 |
|---|---|---|
| 高 | 盈余 | 经验正增长（快速） |
| 低 | 盈余 | 少量正增长（维持） |
| 高 | 亏空 | 经验负增长（练伤自己） |
| 低 | 亏空 | 缓慢负增长（坐吃山空） |

- 实现：`player:getXp():AddXP(Perks.Fitness, delta)` 与 `Perks.Strength` 同样处理。
- 钳制：单日经验 delta 上限防刷；耐力上限修正 clamp ±20%；多病并发归一化。

### 4.5 体重联动（第一版）

**关键原则：不独立计算 `△Weight`，不与原版体重公式并行运行。** 原版体重公式 `△Weight = weightGainFactor × calorieProportion × timeElapsed` 已经包含卡路里/碳水/脂肪的累积与衰减逻辑，若 MOD 再独立算一套增重会导致**双重计算**。

正确做法：通过 `player:getNutrition()` 对象读写原版累积值，间接驱动原版权重公式。

| 触发条件（7 天均值） | 对原版营养对象的操作 | 预期体重效果 |
|---|---|---|
| 热量盈余 + 运动量低 | `nutrition:addCalories(smallBonus)`、`nutrition:addCarbohydrates(smallBonus)` | 原版公式自然算出 +0.1kg/周期 |
| 热量盈余 + 运动量高 | `nutrition:addProteins(bonus)`（肌肉），不额外加碳水 | 体重稳定，力量优先 |
| 热量亏空 + 运动量高 | `nutrition:addCalories(negative)` | 原版公式算出 -0.15kg/周期（先脂肪后肌肉） |
| 热量亏空 + 运动量低 | `nutrition:addCalories(smallNegative)` | 缓慢掉重 |

- 体重阈值联动：<55kg 加快力量流失；>95kg 耐力恢复惩罚（肥胖负担）。这些阈值通过**读取** `nutrition:getWeight()` 判断，不写入。
- 原版/Fitness 经验封顶 trait 逻辑**保持原样生效**，我们不绕过。
- **禁止**直接 `setWeight()` 或独立维护体重变量。

### 4.6 营养疾病系统

#### 4.6.1 疾病模型（统一表驱动）

- 触发：某营养素**7 天均值 < 阈值连续 N 天** → 进入"潜伏 → 轻度 → 中度 → 重度"（0-3 级）。
- 恢复：补充达标连续 M 天 → 逐级下降。
- 疾病可多病并发，惩罚**归一化累加**（见 4.4.4），防止属性爆负。

#### 4.6.2 疾病清单与负面表现（v1 共 5 种）

| 疾病 | 缺失营养 | 负面表现（按阶段递进 0→3） | 状态量 |
|---|---|---|---|
| 坏血病 | 维生素C | 伤口愈合 -20%/-40%/-60%；疲劳恢复 -10%/-25%/-40%；重度持续失血倾向 | `scurvy_level` |
| 贫血 | 铁 | 耐力上限 -10%/-20%/-35%；运动耗耐力 +15%/+30%/+50%；重度偶发眩晕（操作失灵 ≤0.5s，单日不超过 3 次） | `anemia_level` |
| 电解质紊乱 | 钠/钾 | 耐力恢复 -20%/-40%/-60%；随机"抽搐"（≤0.5s 无法行动，单日不超过 5 次）；重度间歇视野摇晃 | `electrolyte_level` |
| 消瘦 | 蛋白/热量 | 皮肤苍白；受伤 +10%/+20%/+35%；耐力恢复 -10%/-25%/-40%；重度负重大幅下降 | `wasting_level` |
| 夜盲症 | 维生素A | 夜晚视野 -20%/-40%/-60%；光源半径 -20%/-35%/-50%；重度看不清 5 米外 | `nightblind_level` |

> **v2 预留**：脚气病（维生素B1 缺失）、骨质流失（维生素D/钙 缺失）不在 v1 实现，数据表与状态量字段已预留。

#### 4.6.3 症状实现与视觉

- 数值层：修改 `stats.endurance`（直接写字段，PZ Stats 类 endurance 为公开字段）、`bodyDamage` 相关接口、负重上限等原版接口。
- 视觉层：苍白肤色用 `getHumanVisual()` 调色；夜盲用"夜间屏幕蒙层"（全屏半透明黑 `ISUIElement`），不依赖 B42 光照 API。
- 交互层：抽搐/眩晕用操作锁定，**持续时间 ≤0.5s 且设单日触发上限**（见 4.6.2 表），避免让玩家觉得"游戏在跟我作对"。不新增与 Moodle 冲突的新心情图标。

### 4.7 UI 面板

#### 4.7.1 入口

- N 键（可配置）打开/关闭，界面右上角按钮备用入口；仅客户端文件，单机直接可用。

#### 4.7.2 布局

```
┌──────────────────────────────────────────┐
│ [营养状态]   [趋势]   [健康]   ← ISButton 标签页
├──────────────────────────────────────────┤
│ 蛋白质    ████████░░  78%  达标          │   ← 当日盈余/需求 进度条
│ 碳水      ██░░░░░░░░  22%  不足          │
│ 脂肪      ██████████ 100%  过量          │
│ 钠/钾     ████░░░░░░  43%  注意          │
│ 维生素A   █████░░░░░  52%                │
│ 维生素C   ░░░░░░░░░░   5%  危险          │
│ ...                                      │
├──────────────────────────────────────────┤
│ 7天均值趋势：蛋白质 +0.3 | 碳水 -0.2 ...  │   ← sparkline
├──────────────────────────────────────────┤
│ 诊断：坏血病（中度）— 补充维生素C        │   ← 疾病诊断+建议
│ 今日运动量：62%                          │
└──────────────────────────────────────────┘
```

- **状态页**：每营养素一行（名 / 进度条 / 数值 / 状态标签）。
- **趋势页**：7 天均值，每营养素一行极简 SVG 折线（点数 7）。
- **健康页**：疾病等级、症状、恢复进度、改善建议。

#### 4.7.3 组件技术

- `ISPanel` 自绘，无外部图表库；sparkline 用点+线绘制。
- 标签页、按钮、tooltip 用原版 `ISButton` / `ISToolTip`。
- **渲染节流**：面板刷新每 0.5s 一次（用时间戳累加器），避免每 tick 重绘；进度条数据从 `modData` 读取，不直接驱动结算逻辑。

## 6. 测试策略

### 6.1 分层

| 层 | 方式 | 工具 |
|---|---|---|
| 逻辑单元测试 | 评分/疾病阈值/消耗公式写成纯函数 + 独立断言脚本 | luajit（PZ 同款 Lua 5.1 JIT） |
| 集成测试 | 沙盒开局 + 控制命令快速造境 | 游戏内 debug（加食物/跳时间/看日志） |
| ModData 持久化 | 吃指定食物→读档验证数值保持 | console + 存档检查 |

### 6.2 关键验证用例

1. 摄入结算：吃 100g 罐头豆 → 营养值折算正确。
2. 运动消耗：冲刺 30s → 碳水/无机盐按倍率扣减；翻越 → 瞬时 -30 碳水。
3. 长期成长：7 天盈余+运动 → Fitness/Strength 正增长；7 天亏空+运动 → 负增长。
4. 疾病触发/恢复：连续 3 天缺 VC → 坏血病潜伏→轻度；补 2 天 → 逐级恢复（含读档持续）。
5. 体重联动：热量盈余+少动 → `getNutrition()` 累积值变化驱动原版公式自然增重；原版 Fitness 封顶逻辑仍生效。
6. 并发防爆：5 病全触发 → 惩罚归一化，无负数/NaN。
7. 性能：1 游戏小时 CPU 增量在阈值内（每秒结算用累加器，UI 0.5s 节流）。
8. 输入锁定体验：贫血眩晕/电解质抽搐单次 ≤0.5s，单日不超上限，玩家不感到失控。

### 6.3 调参

所有参数集中 `Nutri_Config.lua`，测试即调参。

## 9. 验收标准

1. 吃多/吃少/运动多/运动少四种组合下，体力耐力出现可感知的短期与长期差异。
2. 5 种疾病均可触发、演进、恢复，症状与原版系统正确联动且并发不爆表。
3. 营养面板正确展示状态/趋势/疾病，风格与原版一致无违和。
4. 体重变化通过 `getNutrition()` 累积值驱动原版公式自然产生，原版 Fitness 封顶机制不被破坏，无双重计算。
5. 数据表驱动，改 `Nutri_Config.lua` 即可平衡，无需改逻辑代码。
6. 进食跟踪通过 `ISEatFoodAction` Hook 实现，不依赖不存在的 `OnEatFood` 事件。
